**Date:** 2026-07-18
**Scope:** Full codebase audit — 25 Java files, ~2,200 LOC

## Implementation Status

| Component | Status | Notes |

### What is implemented

- `CrowEntity` — full entity with AI goals, data sync, GeckoLib animation
- `ScavengeGoal` — priority-based item pickup with satiation cooldown
- `SwarmDistressGoal` — retaliation and swarm combat modes
- `SwarmManager` — singleton coordination with escalation tracking
- `CrowNestBlock` + `CrowNestBlockEntity` + `CrowNestStateMachine` — full lifecycle
- `CrowNestSeekGoal` — BFS-based nest finding (32-block radius)
- `CrowSpawning` + `CrowNestFeature` — biome spawning and procedural placement
- Networking — `DistressPayload`, `ScavengePayload` with codecs
- Registration — entities, blocks, items, sounds, features
- `CrowNestStateMachineTest` — full lifecycle unit test

### What is NOT yet implemented

- Client-side network handlers are **empty stubs** (no visual/audio feedback for distress/scavenge)
- Block entity renderer for nest (commented out)
- Baby crow model registration (commented out)
- Custom particles (commented out)
- Sound OGG files (referenced but absent)
- Texture PNGs (`crow.png`, `crow_nest.png`, `icon.png` — absent)
- `BLACK_OIL_SUNFLOWER_SEEDS` crafting recipe (absent)
- Crow entity loot/drop table (absent)
- Mixins (both configs are empty)
- `CrowNestBlockEntityTest` is a stub
- `getBreedOffspring()` returns `null` (baby spawning is nest-based, not vanilla)
- `onNonCrowDamaged` in SwarmManager is empty (no-body method)

## PAWS Review by Component

### 1. `CrowEntity` (344 lines)

| Pillar | Rating | Findings |
|---|---|---|
| **P**erformance | ⚠️ Medium | `followOwnerPerch()` runs every tick while perched, computing `sqrt(distSq)` then `Math.min(sqrt(distSq) * 0.5, 0.3)` — redundant sqrt. Could use `distSq` directly. |
| **A**uditability | ✅ Good | All state changes go through `entityData.set()`. Taming, perching, breeding are traceable. No debug logging in runtime path. |
| **W**orkability | ⚠️ Medium | `getBreedOffspring()` returns `null` — works because nesting handles spawning, but breaks if vanilla code calls it. `registerGoals()` has a gap: priority 3 is skipped (goals at 0,1,2,4,5,6). Baby crows get `FollowParentGoal` at priority 2, which conflicts with adult `TemptGoal` also at priority 2. |
| **S**calability | ✅ Good | Clean separation of concerns. Goals are external classes. Animation controller is isolated. |

**Risk:** Goal priority conflict — both adult `TemptGoal` and baby `FollowParentGoal` use priority 2. If a baby somehow reaches adult code path, goals collide.

### 2. `SwarmManager` (287 lines)

| Pillar | Rating | Findings |
|---|---|---|
| **P**erformance | ⚠️ Medium | `findNearbyCrows()` inflates AABB by `sqrt(1024)=32`, queries all crows, then re-filters by `distanceToSqr`. The AABB query is O(n) for all entities in a 64×64×64 region. `escalationHistory` uses `System.currentTimeMillis()` — wall-clock time, not game ticks; precision issues across dimensions/servers. `ConcurrentHashMap` overhead is unnecessary for single-threaded Minecraft server. |
| **A**uditability | ⚠️ Low | No logging of swarm activation, escalation triggers, or cooldown resets. Singleton `INSTANCE` with no dimension awareness — crows in different dimensions share cooldown state. |
| **W**orkability | ⚠️ Medium | **Critical:** Singleton is **not dimension-aware**. A crow in the Nether shares the same cooldown map as one in the Overworld. `escalationHistory` uses `ArrayList` (non-thread-safe) inside `ConcurrentHashMap.computeIfAbsent` — race condition on the inner list. `onNonCrowDamaged()` is an empty method. |
| **S**calability | ⚠️ Low | Singleton pattern violates modularity. No way to unit-test without global state. Tight coupling to `CrowEntity` internals (`getSwarmGoal()`, `dropCarriedItem()`). |

**Risk (HIGH):** Cross-dimensional cooldown leakage. Two crows with the same entity ID in different dimensions would share cooldown state. The `crowId` key should be `(dimension, entityId)`.

### 3. `ScavengeGoal` (209 lines)

| Pillar | Rating | Findings |
|---|---|---|
| **P**erformance | ✅ Good | Uses `distanceToSqr` throughout. Search radius is 1.0 block (very small AABB). `findBestItem()` iterates candidates once per priority tier. |
| **A**uditability | ✅ Good | Clear state transitions (IDLE → CARRYING). Broadcasts `ScavengePayload` on pickup. Sound effect on pickup. |
| **W**orkability | ✅ Good | Proper null checks on `ServerLevel`. Edge case: if `targetItem` is null after `findBestItem`, `start()` returns without error. Cooldown properly scales with satiation. |
| **S**calability | ✅ Good | Self-contained goal class. No singleton dependencies. Clean tag-based priority system. |

**Minor issue:** `start()` directly removes the `ItemEntity` and sets it to `ItemStack.EMPTY` before removal — if the entity was already removed by another system, this could cause issues. Should check `itemEntity.isAlive()` before manipulation.

### 6. `CrowNestSeekGoal` (144 lines)

| Pillar | Rating | Findings |
|---|---|---|
| **P**erformance | ⚠️ Medium | BFS explores a 65×65×65 cube = **274,625 blocks**. `BitSet` is efficient but this runs every tick in `canUse()`. For a mating crow, this fires every AI tick (~4 game ticks). Consider caching or reducing search frequency. |
| **A**uditability | ✅ Good | Timeout mechanism (1200 ticks = 60s) prevents infinite searching. Clear state reset on timeout. |
| **W**orkability | ⚠️ Medium | `queue.add(start)` is called **twice** (lines 104 and 107) — redundant but harmless since visited check catches it. `enterNest()` checks block type but not block entity stage — could trigger `startIncubation()` on a nest already incubating (though `startIncubation()` is guarded by `STAGE_IDLE` check). |
| **S**calability | ✅ Good | Self-contained, no shared state. |

**Performance concern:** BFS over 274K blocks per AI tick is expensive. Recommend throttling to once per 20 ticks or using a precomputed spatial index.

## Recommended Improvements (Prioritized)

1. **Fix `SwarmManager`** — Add dimension key to cooldown maps; replace `System.currentTimeMillis()` with game ticks
2. **Throttle BFS** in `CrowNestSeekGoal` — Cache result or limit to once per 20 ticks
3. **Complete client handlers** — Implement visual/audio feedback for `DistressPayload` and `ScavengePayload`
4. **Replace reflection** in `ModClientEntities` with direct Fabric API usage
5. **Add assets** — Sound OGGs, texture PNGs, crafting recipe for seeds
6. **Refactor `CrowNestBlockEntity`** constructor for testability
7. **Fix goal priority conflict** in `CrowEntity`
